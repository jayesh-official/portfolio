# AGENTS.md

Static portfolio site (Bootstrap 5 + vanilla JS), assembled from HTML partials by
plain PHP scripts. No framework, no bundler, no tests, no linter.

## Source of truth

- **Edit `partials/*.html`, `css/style.css`, `js/main.js` — never the root `index.html`.**
  Root `index.html` is generated by `php build.php` and **is committed**, so after any
  partial/CSS/JS edit you must regenerate it and commit it alongside the source change.
- `dist/` is gitignored and built by CI. Never commit it or hand-edit it.

## Commands (PHP CLI must be on PATH — XAMPP)

```
php build.php            # dev: regenerate root index.html from partials/   (npm run build:dev)
php build.prod.php       # prod: minified site into dist/                   (npm run build)
php -S 127.0.0.1:8000    # local preview (serves repo root)
npm run optimize:images  # DESTRUCTIVE: re-encodes img/ in place (needs `npm i`)
```

Verification is just: run `php build.php` then `php build.prod.php`; both exit non-zero
on missing partials and print output/size summaries. There is nothing else to run.

## Gotchas that are easy to get wrong

- **Adding/renaming/removing a section touches 3 places:**
  1. `partials/<name>.html`
  2. the hardcoded `$order` array in **both** `build.php:15` and `build.prod.php:33`
     (they must stay identical, otherwise dev and prod HTML differ)
  3. the nav links in `partials/header.html`
- **New images must be added to the hardcoded `$imgMap` in `build.prod.php:272`**,
  otherwise the file silently never ships to `dist/` (build only WARNs).
  Reference counts are hardcoded: `img/laracon/{1..15}.jpg`, `img/certificates/{1..5}.png`.
  `tools/optimize-images.mjs` hardcodes the same counts and **overwrites source images**
  (all three loops live in `build.prod.php:280-281` and `tools/optimize-images.mjs`).
- **SEO/JSON-LD lives in `build.prod.php`, not in partials**: `SITE_URL`, `SITE_TITLE`,
  description/keywords, JSON-LD `email`/`sameAs`, and the hardcoded `TODAY` sitemap date
  are all constants near the top of that file. Dev builds have a different `<head>`.
- The CSS/JS minifiers are homegrown scanners inside `build.prod.php` (`minify_css`,
  `minify_js`, `minify_html`). If prod output breaks, fix them there — there is no
  minifier package. `minify_html` strips HTML comments and collapses all whitespace,
  so commented-out markup exists only in dev.
- **Deploy (`.github/workflows/deploy.yml`) only triggers on pushes to `main` touching
  `partials/`, `css/`, `js/`, `img/`, `build.prod.php`, or the workflow file.** Editing
  README/package.json/etc. will not deploy. The workflow runs `php build.prod.php` and
  force-pushes `dist/` to `gh-pages`; PHP 8.2 is provisioned by the workflow, not needed
  locally for CI.
- Asset paths are intentionally **relative** everywhere so the site works under the
  `/portfolio/` GitHub Pages subpath — don't switch to root-absolute URLs.
- Contact form posts to a Formspree endpoint in `partials/contact.html`.
